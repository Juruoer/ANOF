# ANOF Web 界面

ANOF Web 让你在浏览器中管理私人空间和公共空间的文件。登录后，可以整理目录、上传和下载文件、使用回收站；管理员还可以邀请家庭成员、管理账户和存储额度。

日常使用从管理员提供的 HTTPS 地址开始。例如，要上传一份照片，进入“传输管理”，选择目标目录和本地文件，再开始上传。页面会先计算文件摘要，随后显示服务器确认收到的大小；看到“发布已确认”后，文件才已经进入目标目录。

## 打开与登录

网站应按[部署说明](../deploy/README.md)提供页面与 API，共用同一个 HTTPS 地址。使用支持 JavaScript、Cookie、IndexedDB、Web Worker、WebAssembly 和 Web Locks 的现代浏览器。IndexedDB 用来保存上传恢复线索，Web Locks 用来防止两个标签页同时写入同一上传；缺少 Web Locks 时，页面会禁用上传写入和恢复。浏览器存储不可用时也无法新建上传。

已有账户可以直接登录。新成员取得邀请码后，先注册，再用新账户登录。注册不会自动建立登录会话。“账户资料”可以修改显示名称，“修改密码”成功后需要重新登录。

如果登出显示结果未确认，页面会先清除受保护视图，服务器会话却可能仍有效。你可以点击“重新核对身份”，也可以再次登出或重新登录。重新切回页面不会自行恢复账户；主动核对成功只说明会话当前有效，不证明上次登出成功。完整刷新页面会重新向服务器核对身份，请注意它与当前页保持匿名的行为不同。

## 整理和下载文件

进入“文件管理”，选择“我的空间”或“公共空间”。空间入口显示额度、已用量和上传预留量；公共空间还显示本人贡献额度。打开目录后，可以新建子目录、重命名、移动或复制文件。

名称只填写单个文件或目录名，不填写路径。移动限于同一空间；复制只支持单个文件，可以选自己的私人空间或公共空间。选择目标后需点击“选用此目录”确认。公共目录可能包含其他成员的内容，具体操作权限由服务器检查，管理员也不能因此查看其他成员的私人文件。

搜索按名称字面匹配，`%`、`_` 和斜杠不会变成通配符或路径。列表逐页显示，每页最多 100 项；只保留当前页和最多四个返回位置，更早的内容可从列表首页重新查询。分页期间其他人的修改可能改变结果顺序。

点击下载链接后，由浏览器处理保存位置和文件名，某些特殊字符可能被浏览器替换。是否下载完成应看浏览器的下载记录；页面点击成功不能证明文件已收到。Web 不提供自制下载续传工具。

### 回收站与冲突

移入回收站的文件仍占用额度。你可以查看条目并恢复到原位置；原目录不可用或名称冲突时，需要重新选择目录和名称。永久删除前要勾选确认，操作不可撤销；成功提示表示逻辑删除，服务器回收磁盘内容可能稍后完成。

编辑时若提示版本冲突，先看刷新的资料，再决定是否重新提交。遇到“操作结果未知”，应先查询当前状态，不能把报错理解为操作一定未发生。页面不会自动重发写入；即使读回的内容与预期相同，也不能单凭这一点确认先前请求的结果。

## 上传文件

在“传输管理”中按以下顺序操作：

1. 选择空间和目录，点击“选用此目录”。
2. 选择本地文件，点击“加入上传队列”。队列最多容纳 16 个文件。
3. 点击“开始上传队列”。页面一次处理一个文件，先计算完整摘要，再分块上传。
4. 等待“发布已确认”。服务器接纳了验证或发布任务时，页面可能仍显示待处理；这时文件尚未被确认为可用。

单文件长度上限为 1 TiB，实际可上传大小还受空间额度、服务器预算和浏览器运行条件限制。文件计算摘要期间需保持页面运行；哈希单块等待最多 30 秒、整次最多六小时。队列不会预先读取所有文件。

如果服务器报告名称或目录问题，页面会等待你选择同一空间中的目标目录、填写完成目标名称，再点击“使用所选目录再次完成”。它不会自动改名或覆盖已有文件。一个文件尚待处理或需要选择目标时，后续队列也会停下来。

### 中断以后怎样继续

离开传输页面、关闭页面、登出、改密或身份重新核对会停止本地调度。已经被服务器接受的任务仍可能继续执行，页面关闭不保证后台上传完成。

重新登录后，在“本地恢复记录”找到对应文件，重新选择原文件，再点击“验证文件并恢复”。页面会重新计算完整摘要，核对当前账户和服务器记录，从服务器确认的位置继续。名称相同不代表内容相同；长度或摘要不同会拒绝恢复。重新登录和刷新页面都不会自动开始上传。

遇到未确认的创建、追加、完成或取消请求，先用“核对服务器状态”检查。找不到记录、记录失效或核对不一致时，页面会停止，不自动创建替代上传。若看到历史结果已删除，也不会重新发布它。服务器仍在验证或发布时，可以稍后再次检查。

下面几个按钮的作用不同，选择前请看清对象：

| 操作 | 结果 |
| --- | --- |
| 暂停本地上传 | 停止当前页面的工作；服务器可能仍有上传记录和预留空间 |
| 清除未开始队列 | 移除尚在本地排队的文件，不删除服务器上传 |
| 取消服务器上传 | 请求服务器逻辑取消，需勾选确认；磁盘清理可能尚未结束 |
| 仅删除本地记录 | 丢弃当前浏览器中的恢复线索，不取消服务器上传，也不释放服务器预留 |

没有本地记录时，仍可用“服务器上传首页”查看上传状态并明确取消。不要为了消除错误提示而直接清空浏览器存储：库结构损坏时页面会保留现场并拒绝操作，服务器责任不会因此消失。

本地恢复记录最多 64 条，满额时需主动清理不再需要的记录。终态记录按本地首次确认时间保留七天，在访问记录库时清理；活动和结果未知的记录不会自动淘汰。浏览器时钟跳变会影响实际清理时机。不同账户只显示各自已核对身份下的记录，记录不包含文件内容、密码或会话凭据。

## 管理家庭成员与额度

管理员从“管理员管理”进入用户、邀请、配额和存储预算页面。停用账户会使该成员的旧会话失效，重新启用后仍需重新登录。此处不提供角色修改或替用户远程改密。

创建邀请时填写使用次数和有效秒数。成功后点击“显示一次性邀请码”，交给新成员后点击“已完成交接，清除秘密”。邀请码只短暂显示，最多两分钟；隐藏页面、离开管理页或登出会清除它，邀请列表无法再次取回明文。创建结果未知时先核对邀请元信息，不要直接补建。撤销邀请码不影响已经注册的账户。

额度以十进制整数填写字节数和节点数，两项一起提交。服务器不会接受低于当前已用量与预留量的额度。存储预算页面将已计费内容和预留量相加；待回收、隔离、不可用等统计是其中的分类，不能再次累加，也不表示这些空间可立即释放。磁盘采样不可用时不能按零剩余空间理解。备份和离线维护请使用[部署维护入口](../deploy/README.md)。

## 从源码构建

开发者和部署者先按[构建说明](../BUILDING.md#构建-web)准备 Linux x64 Node 24.22.1 和 npm 11.19.1，再从 `web/` 目录执行：

```sh
./scripts/npm.sh ci
./scripts/npm.sh run tools:check
./scripts/npm.sh run build
```

`ci` 按锁文件安装依赖，需要相应包缓存或 registry 访问；构建不会下载 Node、浏览器或后端。`build` 先做类型检查，再生成 `dist/`，其中含页面、Worker/WASM 资产和第三方许可。部署时发布完整目录，浏览器运行不需要 Node/npm。hash-wasm 的运行时许可见 [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt)。

脚本优先选择 PATH 中版本匹配的 Linux Node，也支持已有私有工具目录以及 `ANOF_NODE`、`ANOF_NPM` 显式选择；不要求每台机器都有 `.tools` 副本。选择方式和安装步骤统一见[构建说明](../BUILDING.md#nodejs)，不要用 Windows npm 或 `latest` 替换锁定工具。

本地修改页面时可从 `web/` 执行：

```sh
./scripts/npm.sh run dev
```

服务监听 `127.0.0.1:5173`；构建后可用 `./scripts/npm.sh run preview` 在 `127.0.0.1:4173` 预览。端口占用即失败，静态服务不转发 API。涉及登录和文件的完整操作仍需[同源 HTTPS 部署](../deploy/README.md)，不要通过放宽 CORS 或关闭证书验证来接入。

修改实现时请阅读[请求、身份与传输设计](DESIGN.md)；检查改动的方法与浏览器夹具配置见[测试说明](TESTING.md)。
