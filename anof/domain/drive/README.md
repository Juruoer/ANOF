# 云盘领域值与策略

这里定义文件树、额度、回收站和内容状态的规则。应用取得节点和内容记录后调用这些规则，再决定能否修改以及怎样计费；领域层本身不读取数据库或磁盘。

## 树和搜索

移动或删除子树前，[TreePolicy.h](TreePolicy.h) 和 [DrivePolicy.cc](DrivePolicy.cc) 检查节点是否组成完整的树、归属是否正确，以及目标位置是否超出深度限制。重复 ID、断链、环、跨空间节点或文件拥有子节点都会被拒绝。整树最多 1000 个节点，活动节点最多 128 层。

两个节点可以引用同一份内容，但逻辑额度仍按每个文件节点计费，并按创建者 `createdBy` 汇总。

`SearchText` 接受 1～128 字节的 UTF-8 文本并检查控制字符，保留空格、大小写和通配符的字面含义。查询本身由数据库适配器执行；`QueryBudget` 给出 100 ms、10000000 条指令和 100000 个候选的上限，调用者只能收紧它。

## 回收站与内容状态

[Trash.h](Trash.h) 定义回收站条目及 30 天保留期。[Blob.h](Blob.h) 区分文件内容的固定描述和它的生命周期状态：普通内容失去最后引用后，经过 24 小时宽限才可能进入清理。

UNAVAILABLE 表示已登记的异常内容，保留原内容身份、文件证据和计费字节数。即使它没有引用，也不会自动成为清理候选。普通 Available/Deleting 内容的计费应与长度相等；Missing、Length、Hash 异常分别要求相应证据。

`validateStorageStatistics` 检查待清理、隔离、不可用占用之间的关系及求和溢出。这些统计属于已保留物理占用的子集，不能再加到总占用里。领域判断只选出清理候选，真正删除前 runtime 仍要取得排他资格。

## 节点名额

[NodeAccounting.h](NodeAccounting.h) 保证 used+reserved 不超过 100000；预留、发布与释放均为不修改输入的受检纯计算，零变化不推进版本，溢出或下溢失败。额度释放与物理占用释放分别计算，不混淆两个账本。
