# 文件与回收站管理

这里把目录树上的操作组合成事务。[CreateDirectory](CreateDirectory.h) 创建目录，[DriveService](DriveService.h) 处理移动、重命名、单文件复制、移入回收站、恢复、永久删除和搜索。它们在元数据线程运行，文件内容的读写和删除由 runtime 调度。

## 修改一个节点

每次请求先验证会话与空间权限，再检查资源条件。`DriveCondition` 保留条件所属的节点或回收站条目、ID 和版本；类型不同的条件即使 ID 和版本碰巧相同，也会失败。修改后、提交前还会复验身份，相关审计与业务状态在同一个事务中写入。没有实际变化时不增加版本、事件时间或审计。

私有空间只对所属用户可见。公共空间中涉及多个创建者的子树，只有管理员能整体修改。树操作最多处理 1000 个节点，深度最多 128 层；搜索使用仓储提供的查询预算，分页绑定用户、空间、查询和过滤条件。

创建目录同时更新逻辑额度和全局节点账本。复制文件创建新的节点 ID，由调用者拥有，并重新计算逻辑额度和节点数；内容仍引用原来的 AVAILABLE Blob，因此不重复占用物理内容空间。

## 回收站与内容清理

移入回收站和恢复都保留原有用量。永久删除才按节点及原创建者扣除逻辑用量，同时为仍保留的已完成上传记录写入“结果已删除”信息。最后一个引用消失时，记录内容无引用的时间，磁盘空间随后由内容清理释放。

[MaintenanceService](MaintenanceService.h) 供后台维护调用。到期删除会重新核对时间和版本，与用户永久删除共用 [PurgeTree](PurgeTree.h) 的账本和审计处理。内容删除分为三步：事务标记 DELETING，事务外删除文件并同步目录，再用新事务确认并释放物理计费。提交未知时由 runtime 打开新连接核对，不重复扣账。

损坏的 UNAVAILABLE 内容不能被复制，但其节点仍可改名、移动或删除。最后引用移除后仍保留损坏证据和物理计费，不进入普通垃圾回收。

## 与上传和恢复的关系

上传 PATCH 不依赖目标父目录仍处于活动状态；完成上传和发布文件时才复核目标。目标冲突会保留 READY 状态和预留额度，供用户选择新目标。

[TransferRecovery](../transfer/TransferRecovery.h) 在启动时核对活动节点、回收站节点、共享内容、节点账本和上传删除证据。遍历回收站使用完整时间范围，但到期删除始终以原始 UTC 判断。节点事件时间不会倒退，认证和到期判断仍使用原始 UTC。

实现与失败行为可参考[文件管理服务测试](../../../tests/integration/DriveService_unittest.cc)和[维护集成测试](../../../tests/integration/Maintenance_unittest.cc)：前者侧重权限与原子计量，后者还涉及真实文件删除和恢复。
