# 实例维护应用

本目录提供实例初始化、启动准备、同步离线检查/受限修复，以及停机备份与新目录恢复用例。访问实例时，用例通过端口取得并持有实例锁；应用通过类型化端口读取证据、组合数据库与文件操作。命令行参数和报告输出由 [CLI](../../../apps/anof/README.md) 处理。

## 初始化和启动准备

[InitializeInstance](InitializeInstance.h) 将配置、数据库引导和格式发布组合起来，中断后通过已有 pending 记录完成发布。[PrepareInstance](PrepareInstance.h) 则用于启动既有实例：依次取得锁、读取与校验配置、执行维护检查，再把持锁结果交给 runtime。两者都不会替调用者启动 HTTP。

## 先检查，再决定是否修复

[FsckService](Fsck.h) 的 `inspect` 取得既有实例排他锁，将数据库、旁文件（sidecar）和配置原样复制到外部工作目录，再通过检查 reader 读取副本。源 SQLite 不打开，检查也不调用在线恢复。Quick 核对结构、引用、账本、文件归属及长度；Full 增加完整 SHA-256。检查前后重新捕获现场摘要；变化、取消或无法完成的检查不产生可执行计划。

报告使用类型化计数与可选 `FindingSink`。详细 finding 最多 10000 条，超出仍继续计数，报告标为 Incomplete。元数据页最多 200 项，文件适配按 64 KiB 分块读取。计划最多 10000 动作，确定性编码受 16 MiB 限制；不包含 SQL、秘密或任意文件路径。非法目录项、无法解释的结构及已有未完成运行会阻止生成计划。

## 执行和接续修复

`apply` 要求显式确认、完整类型化计划及外部新原始副本目录。首次执行重新检查、重新生成合法动作，与计划比较；原始数据库/sidecar/配置副本同步发布后，才打开源修复 session。原始副本不是产品备份，不能据此自动恢复文件。

支持的动作包括账本重算、未确认上传尾部截断、单个上传责任恢复、DELETING 清理、孤儿隔离、不可用对象标记和恢复内容的完整哈希确认。它们不改树、名称、所有者或密码，不生成丢失字节，也不自动清空隔离区。

每项动作按 PREPARED → APPLIED → VERIFIED 推进，相关元数据和维护审计共用事务，文件操作在事务之外。隔离在移动前记录 PREPARED 并计费；转为 HELD 不重复计费。DELETING 删除/同步后先记录 APPLIED，再结算，最后验证。完成后重新 FSCK，存在损坏或隔离时仍返回 Findings，不等同于健康。

接续中断的修复时，使用原计划和同一个运行记录。服务会重新校验原始副本、计划摘要、计划外元数据/配置/文件摘要，以及已完成动作的新文件证据和当前元数据后置条件。上传发布的父目录 revision 增量单独归一化；其他目录变动仍被核对。提交或文件效果未知立即停止并关闭 session，后续显式调用才用新连接取证。失败结果中的 `Confirmed` 表示能确认已发生的部分修改，调用者仍需查看阶段和报告，不能把它理解为整个修复完成。

这些方法同步借用 context、端口与 sink，不保留调用方取消标志。调用者须使用专用离线线程，不能在 HTTP I/O loop 内调用。具体逐上传恢复由 [OfflineRecovery](../../runtime/OfflineRecovery.h) 装配，复用 UploadService 的 generation、发布和预留事务。

## 备份与恢复

[BackupService](Backup.h) 同步编排产品备份及新目录恢复。备份只恢复已知上传/DELETING 责任，拒绝任意修账、孤儿认领和 UNAVAILABLE；隔离须明确排除并记录。源独占锁覆盖检查、恢复、导出及复制；数据库和配置只在外部暂存目录中整理为备份格式，引用的共享对象复制一次，活动与回收站节点均保留。副本移除 Session、邀请码、上传和无引用内容并重算账本；不因此删除源责任。

恢复使用完整新配置，检查清单、对象与身份，创建全新实例布局后不覆盖发布。失败保留 staging，发布未知保留操作 ID 与目标，不自动认领或覆盖既有目标。原始修复副本与产品备份是不同格式。外部命令装配及编码由 [CLI](../../../apps/anof/README.md) 提供，本层不解析命令行或 JSON。

## 测试和性能

[真实集成测试](../../../tests/integration/Fsck_unittest.cc) 覆盖只读现场、Quick/Full、计划拒绝、原始副本验证、重复执行、上传恢复、隔离、GC、未知结果重入及取消。目录摘要通过重复扫描保持内存占用固定；目录很大时，这也意味着检查耗时会增加。
