# SQLite 事务与仓储契约

应用以 Store 为一个连接的拥有者，以快照或事务为一次数据库工作的边界。以修改账户为例，应用在写事务中读取账户，按预期版本更新，撤销相应 Session，再追加审计；只有所有步骤成功后才提交。仓储不独立提交，也不自行运行密码计算或文件操作。

## 打开连接与校验结构

连接启用外键、WAL 和 FULL 同步，busy timeout 默认 100 ms，允许范围为 0–5000 ms。竞争超时返回可重试错误，由调用者结束当前作用域、重新读取后决定是否重试。连接、语句及事务留在同一线程，语句必须先于连接销毁。

[current.sql](schema/current.sql) 是 schema 5 的建库定义，由构建嵌入程序。建库以独占、no-follow 方式创建 0600 主库；已有空文件或伴随文件也会导致拒绝，失败现场不会被静默重建。实例层面的路径与初始化顺序见[启动契约](../../InstanceStartupContract.md)。

结构校验在内存中建立参考库，比较实际表、索引和触发器的类型、名称、所属表、SQL 定义及数量，不执行待检库提供的定义文本。完整性检查要求 `PRAGMA integrity_check(1)` 只返回一行 `ok`，并通过外键检查；限制诊断数量不代表检查耗时恒定。

部分 CHECK 使用本模块注册的确定性、innocuous 函数，校验 UUID、登录名、显示名和密码编码形状。它们不做 I/O 或密码哈希，异常不会越过 SQLite C 边界。普通 sqlite3 工具缺少这些函数时不能完整执行相关写入或检查，不应通过禁用约束绕开错误。

## 读快照和写事务

读快照启用 query-only 并开始读事务；一致视图在第一次实际读取时建立。随后读取身份、空间、节点和额度时使用同一视图，另一个 WAL 连接的提交不会改变它。跨多个快照分页则没有同一时刻的保证。Metadata、Transfer、Drive 视图共用活动标记，不能相互嵌套。

写事务使用 `BEGIN IMMEDIATE`。仓储调用失败会污染事务，后续 commit 不能提交此前的局部写入。未提交事务在析构时回滚；清理失败会使连接不可继续使用。提交前还检查文件树、回收站、上传结果和 Blob 持有关系，避免仅满足外键却违反业务结构。

`CommitOutcomeUnknown` 表示 COMMIT 可能已生效。旧连接会失效，调用者应销毁旧 Store，通过新连接读取操作标识、版本和审计等权威证据。不能把未知结果解释为回滚，也不能直接重放扣账或签发凭据。事务不跨网络等待、文件工作、密码计算或 worker 等待持有。

## 身份与账户更新

授权读取同时核对凭据所属 Bearer/Cookie 模式、会话撤销与到期、账户启用状态和凭据 epoch。正常的无效凭据返回 `Unauthenticated`，不合法持久行返回完整性错误。用户列表按 ID seek，每页最多 200 项并多读一行判断后续页；包含停用账户和管理员，不读取密码编码。

显示名和启用状态更新先比较预期 revision，再判断是否无变化或触及管理员保护。停用推进 epoch 和 revision，重新启用只推进 revision。密码更新复核账户启用状态及相关版本，即使新编码相同也按密码变更推进版本。更新时间取本次时间、创建时间和旧更新时间的最大值；无变化操作保留旧时间和版本。

Session 的活动计数涵盖两种认证模式。每用户 32 个活动 Session 的策略由应用在写事务内组合计数、检查和插入，不由仓储自动驱逐旧记录。过期清理单批最多 200 条。邀请消费以条件更新完成，不可用结果统一为 `InviteUnavailable`；注册中的邀请消费、建用户和审计可以一起回滚。首次撤销时间稳定，重复撤销不改写历史。

身份审计使用类型化事件，不保存密码或 token；是否跳过无变化操作的审计由应用决定。管理员密码重置使用本地操作者事件，actor 为空、subject 指向唯一管理员；密码、epoch、Session 撤销和事件必须同事务完成。

## 空间、节点与配额

私有空间按所有者读取，账户停用不会使空间消失，也不会回退到公共空间。可访问空间列表由自己的私有空间和公共空间组成。根目录使用空名称、无父节点和初始 revision 1；插入根节点不隐式扣账，引导调用者负责初始节点计费。

普通节点读取隐藏回收站成员及其后代。路径最多 129 个节点，文件不能作为父目录。子节点按名称二进制顺序及 ID seek，单页最多 200；新文件引用只能指向 AVAILABLE Blob。父目录 revision 由调用者按操作契约推进。

额度上限更新先检查预期 revision，再判断无变化，并要求新上限不低于 used 加 reserved。逻辑空间额度、公共贡献额度和物理容量分别记账，算术溢出视为完整性错误。节点账本的 used 加 reserved 上限为 100000，charge、reserve、publish、release 不代替 Node 或 Upload 写入。调用者在同一事务中组合实体变更、计费和审计。

## 上传与物理计量

上传保留不可变原始参数，可变目标按状态、generation 和 durable offset 条件替换。取消不可逆，包括 COMMITTING；实际变化推进 generation，重复取消不推进。创建时原子检查每用户/全局活动数 8/64、保留数 512/4096，不驱逐历史记录。分页按创建时间和 ID seek；到期扫描排除 COMMITTING，保留清理只删除终态、无 cleanup pending 且超过七天的记录。

物理账本 P 表示已计费内容，R 表示预留；发布将 R 转入 P，清理释放相应预留。已超预算的实例仍可读取和清理，但不能新增超额预留。COMPLETED 上传中的 Node/Blob ID 是历史结果，不阻止内容永久删除；删除事务同时写入 `result_deleted_at` 并推进 generation。Node 到 Blob 仍是强引用。

## 文件树、回收站与搜索

树操作先枚举完整成员，再复验成员、版本、拓扑和内容。写操作最多 1000 个节点，枚举可返回第 1001 个作为超限证据。move 只推进源和不同的直接父目录，移入回收站和恢复推进全部成员及直接父目录；无变化不更新时间。节点删除、额度释放、无引用标记和审计由调用者组合，仓储不隐式重复扣账。

私有回收站只对所有者可见；公共空间普通成员只看到全树由自己创建的条目，管理员可见全部。列表按删除时间和 ID seek，可按根过滤，到期候选单页最多 16。提交前复验成员归属、根/父关系、可达数、节点数、字节数和创建者摘要，拒绝部分移入、部分恢复或孤立条目。

搜索使用字面、区分大小写的 UTF-8 匹配，不拼接 LIKE；同时检查空间和活动祖先。查询预算限制 100000 个候选、100 ms 单调耗时及 10000000 条 VM 指令，每 1000 条指令检查。退出时解除 progress handler；超限返回 `QueryLimitExceeded`，不给部分页面或游标。这是工作预算，不是硬实时保证。

## Blob 生命周期与损坏证据

新 Blob 必须是 AVAILABLE、revision 1，且 `unreferencedAt` 为空；非法输入导致事务失败，不会被静默改写。合法历史无引用对象仍可读取，最后引用移除后的 `markUnreferenced` 才建立首次无引用时间。

引用从实际 Node 和活动 Upload 查询，COMPLETED 上传历史不持有内容。AVAILABLE 对象新增引用时清除无引用标记；无引用满 24 小时后，`markDeleting` 按版本再次确认没有持有者。DELETING 意图不可逆，候选及重试每页最多 16 项。安全删除文件确认后，应用在事务中删除记录、释放 P 并追加审计。

UNAVAILABLE 保留内容身份、Missing/Length/Hash 证据及 `charged_bytes`，禁止新引用并退出普通 GC。最后引用移除也不能把它变回 AVAILABLE 或丢弃损坏证据。AVAILABLE/DELETING 的计费等于原大小；物理总计费还包括隔离条目。统计区分待回收、不可用和隔离内容，DELETING 属于待回收子集，零字节对象也计入个数。相关离线处理见[维护契约](MAINTENANCE.md)。

记录更新时间可按旧记录下界归一化；认证、到期、宽限和审计观察时间使用原始 UTC。不要将仓储的局部时间保护解释为系统时钟单调。
