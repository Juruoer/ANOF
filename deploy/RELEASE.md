# 更新程序与数据格式

更换 ANOF 程序前，先备份实例，并确认新程序支持现有的数据格式。安装新程序只会替换程序文件，不会替你升级数据库。

更新内容见 [CHANGELOG](../CHANGELOG.md)。在客户端使用 `anof --version`，在服务器使用 `anof serve --version` 查询相应机器上的程序版本。

## 数据格式

| 项目             | 格式标识         |
|------------------|------------------|
| HTTP API         | `/api/v1`        |
| 实例目录         | format 5         |
| SQLite 数据库    | schema 5         |
| 备份             | backup_format 1  |
| Web 本地上传记录 | record_version 1 |

程序遇到不支持的实例或备份格式会拒绝打开。不要手工修改版本标记来绕过检查；标记相同也不能代替对具体更新说明的核对。

浏览器中的上传记录与网站地址、实例和用户绑定。更换域名、恢复备份或切换账户后，请先查看服务器上的上传状态，再决定如何处理本地记录。恢复备份不会恢复原有上传任务。

## 更换程序

1. 在另一个目录准备新程序，Web 文件也从同一份源码重新构建。
2. 按[部署说明](README.md#备份与恢复)停止服务并完成备份，保留原来的程序和配置。
3. 安装新程序，检查所需的动态库和配置，然后启动服务。
4. 确认 `/health/ready` 返回成功，再登录检查目录、上传和下载。

如果更换了安装位置，还要修改 systemd 中的 `ExecStartPre`、`ExecStart`，以及 nginx 的静态文件目录。修改服务单元后执行
`systemctl daemon-reload`。

启动失败时，先保留日志和实例目录，查明是配置、依赖还是数据格式问题。需要从备份恢复时使用新目录，具体操作见[备份与恢复](README.md#备份与恢复)
。不要用旧程序直接打开已被新程序修改、且尚未确认兼容的数据。

## 换一台服务器

建议在新服务器上重新编译，或先确认它能加载原程序所需的系统库。仅复制 `anof` 可执行文件会漏掉随安装附带的 SQLite 和 Web
文件；依赖说明见 [DEPENDENCIES](DEPENDENCIES.md)。

迁移后检查服务用户和目录权限、证书、域名、开机启动及备份位置，并实际下载几个文件核对内容。大容量和长时间运行的表现取决于目标机器的磁盘、文件系统和配置；现有小文件测试不能作为容量或吞吐指标。
